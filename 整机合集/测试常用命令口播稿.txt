测试常用命令口播稿（ADB / Linux / ROS2）

一、ADB 命令（安卓设备调试）

面试官你好，我在测试安卓设备或机器人 App 的时候，会用到 ADB 命令。

最常用的几个场景：

第一，连接设备。
手机通过 USB 连电脑后，我用 adb devices 确认设备连接成功。
如果连接不上，我会检查驱动或者重新拔插。

第二，安装和卸载应用。
我用 adb install 加 apk 路径来安装测试包，
用 adb uninstall 加包名卸载应用。
测试中经常要反复安装新版本，这个命令用得最多。

第三，查看日志。
测试中遇到闪退或者异常，
我用 adb logcat 实时查看日志，
配合 adb logcat -c 先清空旧日志，
这样能抓到完整的崩溃信息，
方便我定位是哪个模块出的问题。

第四，抓取屏幕。
用 adb screenshot 可以截取当前屏幕，
复现 bug 的时候我会截图作为证据提交。

第五，查看应用信息。
用 adb shell dumpsys 可以查看应用的各种状态信息，
比如内存占用、activity 栈、权限状态，
排查性能问题或者界面跳转问题的时候会用。

ADB 的核心就是通过电脑控制安卓设备，
让我能完成安装、抓日志、截屏、查看状态这些测试操作。


二、Linux 命令

Linux 是服务器和测试环境最常用的系统，我平时在 Linux 上做环境部署和日志查看。

第一，文件操作。
我用 ls 查看目录内容，cd 切换目录，
cp 复制文件，mv 移动或重命名，
rm 删除文件，mkdir 创建目录。
这些是最基础的文件管理命令。

第二，查看文件内容。
用 cat 直接查看小文件，
用 less 或者 more 分页查看大文件，
用 tail -f 实时跟踪日志输出，
排查问题的时候我会一边跑测试一边看日志。

第三，权限操作。
用 chmod 修改文件权限，
用 chown 修改文件所有者。
部署测试环境时经常需要给脚本加执行权限，
chmod +x 这个命令用得很频繁。

第四，进程管理。
用 ps 查看当前运行的进程，
用 top 实时查看 CPU 和内存占用，
性能测试的时候我会用 top 观察资源使用情况，
用 kill 结束异常进程。

第五，网络相关。
用 ping 测试网络连通性，
用 netstat 或者 ss 查看端口占用情况，
排查服务启动不了或者端口被占用的问题时用。

第六，压缩和搜索。
用 tar 打包和解压文件，
用 grep 在文件里搜索关键字，
排查问题的时候用 grep 配合 tail 过滤日志，
比如 tail -f 日志文件 | grep "error"，
只显示错误相关的日志，效率很高。

Linux 的核心就是让我能在命令行里完成
文件管理、日志查看、进程监控、环境部署这些测试工作。


三、ROS2 基础命令

我在接触机器人测试的时候，会用到 ROS2 的命令，
因为机器人上很多功能模块是通过 ROS2 通信的。

第一，环境准备。
每个终端先 source 一下环境变量，
然后才能使用 ros2 命令。
ROS2 相比 ROS1 最大的区别是不需要启动主节点，
直接就能运行节点，配置更简单。

第二，节点相关。
用 ros2 node list 查看当前运行的所有节点，
用 ros2 node info 加节点名查看某个节点的详细信息，
包括它发布了哪些话题、订阅了哪些话题、提供了哪些服务。

第三，话题相关。
话题是 ROS2 里最常用的通信方式。
用 ros2 topic list 查看当前所有话题，
用 ros2 topic echo 加话题名实时订阅话题数据，
比如订阅机器人的位置话题，就能实时看到坐标数据。
用 ros2 topic pub 加话题名和消息类型可以手动发布数据，
测试的时候我可以主动发指令看机器人怎么响应。
用 ros2 topic hz 查看话题的发布频率，
如果频率忽高忽低，说明数据流不稳定，可能是传感器或者节点有问题。

第四，服务相关。
服务是一问一答式的通信。
用 ros2 service list 查看所有服务，
用 ros2 service call 加服务名和参数调用服务接口，
测试的时候我可以调用机器人的某个服务，
比如让机械臂移动到某个位置，然后看它是否正确响应。

第五，启动和运行。
用 ros2 run 加功能包名和节点名运行单个节点，
用 ros2 launch 加功能包名和启动文件名批量启动多个节点，
测试的时候我一般用 launch 一次启动整套系统。

第六，调试工具。
用 rqt_graph 可视化节点和话题的关系图，
一眼就能看出数据是怎么流转的，
排查通信问题的时候很直观。
用 rviz 可视化机器人的模型、传感器数据、地图和轨迹。

ROS2 的核心就是话题、服务、节点这三个概念，
让我能查看机器人的通信状态、手动发指令验证功能、
以及排查数据流异常的问题。


四、面试官可能追问的问题

Q1：ADB 和 ROS2 有什么区别？
ADB 是控制安卓设备的，
ROS2 是机器人各模块之间的通信框架，
一个是设备调试工具，一个是机器人软件架构。

Q2：你平时在 Linux 上部署测试环境主要做什么？
装依赖、解压测试包、改配置文件、启动服务、
查看日志确认服务正常运行，
主要是这几个步骤。

Q3：ROS2 和 ROS1 最大区别？
ROS1 必须先启动 roscore 主节点，
ROS2 不需要，直接用命令就能跑，
而且 ROS2 支持多机通信，实时性更好。
